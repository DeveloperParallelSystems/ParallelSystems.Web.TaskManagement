## System purpose

Task planning, assignment, review, and delivery for staff, using existing Parallel Systems accounts for login. Visual reference: `reference/parallel_systems_task_management_simplified.html`.

## Components and entry points

- `src/App.jsx` / `src/styles.css`: the approved Inset sidebar design places a white rounded sidebar panel and a matching rounded top bar within 16px desktop page padding and a 16px gutter. The sidebar is 236px wide and sticky, with a shared 80px brand/header height; its navigation area can scroll on short screens. The existing 42px logo artwork, wording and text colors are preserved. Navigation follows Timesheet's dark text, pale green hover/active items, green active border and separated footer, retaining existing routes and unread badge. Mobile panels stack with 10px page padding and wrapping navigation.

- `src/main.jsx`: Redux provider and React Router browser data router at `/task-management/`. The existing dependency supplies `useBlocker` for task-page navigation protection; no dependency or endpoint was added.
- `src/app/store.js`: in-memory authentication, task data, detail cache/request IDs, bulk result state and stale-response guards. Task filters/view are now URL-driven, not Redux state. No account/task data is persisted in browser storage. `loadTaskDetail` fetches the existing detail endpoint; caches are cleared on login/logout/expiry and invalidated on version changes or saves. Bulk actions load full details, compare the selected version, then call the existing save thunk for each task; partial failures are retained per task.
- `src/app/api.js`: credentialed requests exclusively to `/api/task-management`, no-store responses, request header, 20-second JSON timeout and 180-second upload/download timeout. Multipart uploads use XMLHttpRequest for progress/cancellation; downloads use authenticated blobs. Both transports preserve 401 session expiry.
- `src/features/auth/LoginPage.jsx`, `loginFlow.js`: username/email-first login through `/auth/lookup`, then password sign-in or eligible staff account creation through `/auth/register`. The server matches current Staff Information email/account links and fixes new roles to `User`; unknown/duplicate emails and existing inactive accounts cannot register. A successful registration returns to password sign-in. Change and failed submissions clear password fields; request IDs reject stale lookup/registration responses. Form data remains in memory. Email ownership verification is deferred explicitly; email matching alone is the current registration gate. Accounts use the shared account table while login sets only the Task Management cookie. Evidence: sibling `TaskManagementAuthController`, `TaskManagementAccountRepository`, `sp_TaskManagementAccountLookup/Register`, `RegistrationChecks.cs`, frontend `tests/login-flow.test.js`.
- `src/features/tasks/TaskDiscussion.jsx`: separate Discussion panel/form on saved task pages, plain-text comments, one-level replies, edit/delete permissions returned by the API, HTML confirmation dialogs, own-version conflicts and @staff picker. Mentions show staff name/email; candidates have active linked accounts and task access. Review/activity notes remain separate. Drafts are in memory, combine with TaskPage navigation/sign-out guards and survive task-detail saves. Discussion refresh pauses while dirty/saving.
- `src/features/tasks/commentMentions.js`: UTF-16 token ranges, caret-aware suggestions, identity-preserving insertion, span adjustment/removal on text edits, safe plain-text rendering and paged thread merging with retained deleted roots. `discussionState.js` supplies load-page/load-comment/save/delete thunks and per-task request IDs/mutation tokens. Logout/401, task access loss or changed staff bindings clear caches; late responses cannot restore private data. Comment versions are independent of task versions.
- `src/features/tasks/TasksPage.jsx`: board/list, search, URL filters/sorting/quick views, administrator selection, CSV export, and explicit drag status targets. `/` focuses search; App handles administrator C creation; TaskPage handles Escape with unsaved-edit protection.
- `src/features/tasks/taskQuery.js`: validated parse/serialize for `q`, `discipline`, `status`, `project`, `mine`, `quick`, `sort`, `dir`, and `view`; default last-updated descending/board. Unrelated query keys are retained. App and TaskPage preserve query state when opening, returning to the task list and copying task links.
- `src/features/tasks/workflow.js`: shared disciplines/review statuses, quick views, participant-name/description search, stable sorting with missing values last, and existing ownership logic. Created-by filtering requires actual `createdById`; current API omits it, so that quick view is disabled.
- `src/features/tasks/TaskMoves.jsx`, `taskActions.js`: lazy detail permission loading, Move to… fallback, server-allowed drag target checks, admin-only cancellation/reopening checks, complete versioned mutation payloads. Approval/failure opens TaskPage with the intended server-allowed status for a required note before saving. Cached permissions do not replace API authorization/version checks.
- `src/features/tasks/BulkTaskActions.jsx`: admin-only list reassign/due-date form and per-task results/conflict links. Selection snapshots task versions and applies only to currently selected visible rows; successful rows are not rolled back for another row's failure.
- `src/features/tasks/taskCsv.js`: filtered/sorted CSV download, participant lookup names, escaped fields and spreadsheet formula neutralization; no external export service.
- `src/features/tasks/TaskPage.jsx`: full-width routed create/edit page with detail, workflow and activity panels. Existing server-provided transitions, ownership suggestions, required review notes and conflict Reload latest task behavior are retained. Saving an existing task stays on the page and fetches the current version/activity; creation redirects to its returned task ID. `taskNavigation.js` validates GUID/new paths and identifies dirty/saving navigation. `useBlocker` protects sidebar links, task links and browser Back through a native HTML dialog with Keep editing/Discard changes and Escape cancellation. `beforeunload` protects tab reload/close; sign-out confirms dirty edits and is disabled while saving. Session expiry unmounts the task page and clears private workspace state.
- `src/features/tasks/TaskPageTabs.jsx`: controlled Details text tab and History/Attachments icons with semantic tablist/panels, arrow/Home/End navigation and hover/focus tooltips. Attachments is enabled for saved tasks, disabled with “Save this task to add attachments” for new tasks. Details/Discussion and attachment queues remain mounted during tab changes, retaining drafts and navigation guards. History shows task activity, including attachment additions/removals; it does not expose the private comment audit. Evidence: `TaskPage.jsx`, `TaskPageTabs.jsx`, `styles.css`.
- `TaskAttachments.jsx`, `attachmentState.js`, `attachmentValidation.js`: lazy authenticated attachment list, in-memory versioned cache with session/access/staff-binding invalidation, PDF/PNG/JPEG and Word/Excel/PowerPoint (`doc/docx/xls/xlsx/ppt/pptx`) selection up to 10 MB, sequential multipart upload/progress/cancel/retry, private download and confirmed uploader/admin removal. Retry reuses the upload ID; file bytes stay only in component memory. Attachment mutations refresh activity without overwriting unsaved details. The Server supplies permissions, storage validation and independent resource versions. No new dependencies.
- `src/features/tasks/TaskContributors.jsx`: circular initials for the original assignee and reviewer on board/dashboard cards, resolved from existing staff lookups. No Dev/QA text is shown beside the circles. Hover, keyboard focus and tap reveal the role and `First Name, Last Name <email>`; missing emails are identified in the tooltip. Escape dismisses it. Assigned team members remain visible when completion clears the current owner. These show the assigned roles, not an inferred list of historical contributors. Card opening and contributor controls use separate buttons.
- `src/features/tasks/NotificationsPage.jsx`: persistent recipient inbox, unread count, mark read and open task. Workspace refreshes every 60 seconds while visible and on focus; no email or push delivery.
- `/tasks/{guid}`: shareable dedicated task page survives login and reload; `/tasks/new` is administrator-only. The page waits for workspace lookups before loading details. Back to tasks keeps the original query filters/sort/view. Normal API permissions remain mandatory; invalid task IDs redirect to the task list.
- Ownership suggestions follow participant changes unless an administrator explicitly selected a different owner. Approved tasks without a release owner remain with the reviewer, who may complete them directly.
- `src/features/tasks/OverviewPages.jsx`: dashboard, overdue-by-owner/waiting-on-review counts, existing project summaries, and project links that set query state.
- Project cards show a Contributors count and circular initials using the shared `ContributorAvatars` component. `getProjectContributors` deduplicates original assignees, current owners, reviewers and release owners across that project's visible tasks; a person's roles are combined in the tooltip, alongside name/email. Empty projects show No contributors yet. This summarizes current assignments, including retained roles on completed tasks, and does not query historical activity or grant project membership. Evidence: `OverviewPages.jsx`, `TaskContributors.jsx`, `workflow.js`, `tests/task-views.test.js`.
- `src/features/projects/ProjectDialog.jsx`: administrator project creation through Redux and `/api/task-management/projects`; refreshes project cards and task selections after saving.
- Projects and task selectors use shared database projects created from web (`created_from = 1`). Administrators see all web-created projects; ordinary users see only web-created projects associated with their visible tasks. Evidence: sibling server `Database/Stored Procedures/sp_WorkTasksLookups.sql` and `Tests/TaskManagementChecks/Program.cs`. Existing non-web task project references are preserved; this change only filters lookup options.
- All four participant selectors and bulk reassignment use `app.employees` Staff Information IDs/names, including staff without accounts. Lookup fields `firstName`, `lastName` and `email` provide selector labels `First Name, Last Name <email>`, falling back to the display name when name fields are absent and omitting angle brackets when email is absent. `staffOptionLabel` keeps legacy account choices explicitly labelled and disabled. Optional `people.userId`/`accountIsActive` map to login accounts; tracker `allow_access` does not control assignment. Personal views resolve account IDs through those staff links while creator identity stays account-based. Workspace refresh invalidates cached/pending details when staff bindings change. Evidence: `workflow.js`, `TaskPage.jsx`, `BulkTaskActions.jsx`, `store.js`, `tests/task-views.test.js`, `tests/task-mutations.test.js`.
- The sibling server `021_work_tasks.sql` adds staff foreign keys, migrates existing linked participants once with a version increment, preserves unlinked legacy participants/history, and installs `v_WorkTaskParticipants` for current account-link permissions. No new staff/accounts are seeded in application databases. Existing legacy assignments can remain during unrelated edits but cannot be newly assigned; administrators can replace them with staff. Deploy the updated API then this frontend. Invites are still under discussion and not implemented.
- `DeploymentTools/Deploy-ParallelSystems-TaskManagement.cmd` and `.ps1`: Windows EC2 launcher following the Receipts deployment pattern. Requires a clean repository and confirmation, runs locked dependency installation/tests/build, packages only compiled files, and uploads a separate frontend release. Defaults match the existing Timesheet/Receipts EC2 target; no production connectivity was verified locally.
- `DeploymentTools/deploy_task_management.sh`, `configure_task_management_nginx.py`, `task-management.nginx.conf`: separate `/task-management/` releases and app-owned Nginx include within the existing Timesheet content server. Preserves the existing Receipts include, API/health proxies and TLS settings. Uses atomic switching, configuration backups, remote route/asset checks and rollback. Acquires Task Management and existing Receipts locks; Timesheet deployments/manual Nginx edits must be scheduled separately. Requires the updated shared Server, but never deploys it or runs SQL.
